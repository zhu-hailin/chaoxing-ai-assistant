# v1.04 本地课程自动流程

早期验证使用模拟页面；2026-10-09 经用户授权开始现场核对允许的真实课程，最新范围见验证记录。版本保持 v1.04 / npm 1.0.4；不提交、不上传、不改动 `.publish`。入口仍在已有三页导航的「章节」页，包含开始、停止、跳过本章节、自动提交选项和报告；页面打开时不自行开始新任务。

## 模块与调用关系

`build_script.py` 依次合并 core → parser → media → catalog → course-document-bridge → course-page-adapter → course-runner → implementation，交付仍是单个 `.user.js`。

| 文件 | 职责与主要接口 |
| --- | --- |
| `sources/course-document-bridge.js` | 新版跨域连续图片 PPT 的受限消息桥；`courseRemoteReaderFrame()`、`courseDocumentBridgeRequest()`、`initCourseDocumentBridge()`。仅允许已确认的阅读器、直属超星父窗口与固定域名，交换滚动尺寸和错误状态，不交换 Key 或账号。 |
| `sources/course-page-adapter.js` | 读取当前章节、标签、同源 iframe、原生播放器、分页及平台完成状态；`courseFrameTree()`、`courseTabs()`、`courseDocumentReader()`、`courseTaskComplete()`、`courseQuizComplete()`、`courseBlocker()`。 |
| `sources/course-runner.js` | `createCourseRunner(owner, ctl)` 管理队列、取消、超时、运行锁、进度和报告；`initCourseRunControls(doc, ctl)` 连接界面。 |
| `implementation.js` | 使用原控制器展示题目和结果；`checkSnapshot()`、`prefillChecked()` 支持指定题目文档及运行状态检查；手动生成与自动模式互斥。 |
| `sources/assistant-core.js` | 原模型、解密和预填逻辑；模型请求支持 `AbortSignal`，文本控件事件使用所属文档的构造器。 |
| `course_catalog.js` | 原目录、完成标记及成绩隔离；自动运行时锁住手动章节跳转。 |
| `sources/panel-template.html` | 复用章节页，新增开始/停止、自动提交、运行报告与复制；不增加导航页。 |

主课程文档统一调度。任务和目录行的隐藏状态模板不用于判断完成；目录折叠仍保留真实状态。首次任务控件延迟出现时等待加载，每项结束后重读当前页面，避免遗漏随后加入的任务；等待后续任务时区分当前页与其他页面标签。`coursePageTasks()` 将各任务按页面及 iframe 所处顺序排序，资料阅读器按附件容器分别识别，视频与 PPT 混合时不会按类型跳过中间的任务。子测验 iframe 的开始/停止按钮向主文档发送事件，不传 Key 或答案；主控制器持有运行队列，避免题目 iframe 卸载导致流程中断。子页面被替换后移除旧界面监听，防止回调访问失效窗口。

```text
开始 → 固定设置与整份目录队列 → 获取运行锁
  → 章节：已完成则跳过，否则点击原目录入口并等待新内容
    → 页面标签：等待文档真正变化且内容加载完成
      → 全部视频：实际播放与结束 → 等待任务完成标记
      → 可识别资料：原控件到末页 → 等待任务完成标记
      → 章节测验：解密、提取、签名、分批分析、校验、保护性预填
        → 全部题目可靠填写 → 原提交按钮与明确确认 → 等待成功标记
      → 普通文字页面：访问并检查目录状态
    → 本章完成状态确认 → 下个章节
  → 完成/停止 → 释放锁、恢复控件、输出简要报告
```

## 视频与资料

先点击唯一明确的原播放入口或调用原生 `play()`，再等待媒体时长，避免懒加载播放器一直等不到 metadata。读取每个原生 `<video>` 的起始 `currentTime`、`duration` 和实际 `ended`；串行处理当前页面多个视频。正常调用 `play()`，中途暂停时尝试恢复，不写 `currentTime`、不调整 `playbackRate`。播放拒绝、错误、长时间无进展、进度跳转或控件被替换都停止；预计剩余时间仅用于展示。有关实际进度与自动播放限制的接口依据：[MDN currentTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime)、[MDN play](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)。

资料识别连续图片 PPT（`#img.imglook`）与 PDF.js 纵向阅读区域，只沿资料节点祖先和所属 iframe 查找滚动容器，按视口的 80% 逐步滚动；重新读取高度以应对延迟载入，到底稳定两轮后等待任务完成标记。单页资料的有效滚动根允许滚动距离为零，仍等待平台完成标记。无有效尺寸、滚动无响应、页面变化或完成未确认会停止。

资料识别带分页按钮的 Swiper，或提供明确当前页、总页数及末页/下一页按钮的文档阅读器。点击原分页控件并确认末页，再单独等待平台任务完成状态。现场确认的新版 `#img.imglook > iframe#panView` 使用受限消息桥滚动其 `.fileBox` 资料页，仍等待外层平台任务标记；停止/跳过会取消请求。其他未知 PPT 查看器、不可读的跨域 iframe 或缺少状态不会被记为完成；不构造任务完成上报，不调用私有跳过函数。

章节标签、Swiper、人脸层等候选结构参考了 [OCS 超星适配源码](https://raw.githubusercontent.com/ocsjs/ocsjs/4.0/packages/scripts/src/projects/cx.ts)，此处为独立实现，仅采用公开页面结构线索。真实课程是否使用这些结构仍待现场确认；来源代码不能证明本脚本已在真实页面运行。

## 测验与异常报告

沿用统一题目模型、图片模块、每批最多 10 题及所选模型能力限制。图片题不自动切模型；不能分析或可靠预填的题目会列出题号并停止提交。已有不同选项、非空文本、未知题型、只读/富文本或不确定控件继续受保护。

普通一键生成仍只预填。自动模式的「自动提交章节测验」默认开启，来自用户对本功能的明确授权；关闭时预填完成即停留。提交前再次核对题目签名、页面和课程身份，要求无跳过/未确认题且数量一致。只点击唯一明确的原提交按钮，必要时点击唯一明确的原确认按钮；收到已提交/提交成功/已完成标记后才进入下一任务。提交状态超时不重复提交。

测验识别不依赖题目是否仍然显示；明确的完成/提交状态、带分数的完成状态或所属任务完成标记可跳过已交测验。题干里出现“已完成”不作为状态。只有可确认已加载的非任务附件或明确可选标记才直接继续下一页面标签；空 .ans-attach-ct 附件壳不作为加载完成依据，等待真实任务标记及视频/PPT控件，超时则停止；必做任务与可选资料混合时逐项区分，目录仍有未完成任务不能据此判定整章完成。

报告包含章节、视频、资料、提交测验统计，以及异常章节与具体题号/原因；不存 Key、原题答案、图片 Base64 或资源地址。原生控件操作可能产生平台自身请求，模拟请求不能证明真实平台提交成功。

## 生命周期与运行状态

队列、报告和无 Key 的配置摘要按课程、班级和账号范围保存；Key 仅从既有配置读取到本次内存。同一课程采用 DOM 运行锁、带 ownerId 的存储心跳以及可用时的浏览器 Web Locks 互斥。Web Locks 以课程、班级和账号范围命名，只协调同源页面；其余页面通过存储记录检查活跃实例。即使 sessionStorage 会话标识相同，新页面也不能接管仍在运行的实例。只有脚本导航触发 pagehide 并写入 handoff=true、会话和配置均相同，才自动续接原队列；复制标签页不作为交接。旧实例发现 ownerId 改变即停止，不能覆盖新实例的记录。结束、停止及异常均释放浏览器锁。接口依据：[MDN Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)。不增加不同课程间的限制或提示。手动离开/刷新时保存中止报告，不静默重启；改变章节标签、课程或账号会停止。

每个章节使用独立取消信号和闭包。`runner.skip()` 中止当前视频、请求和等待，将章节记为 `skipped` 并进入下一章；迟到回调仍检查原章节上下文，不能填到新章。报告将用户跳过与完成分别统计。停止的章节在同一会话、当前目录不变、无验证拦截且没有结果未明的提交时，用户可点击跳过续接既有队列；开始新队列不自动沿用旧跳过。

看门狗检查人脸识别、验证码、登录过期、交互题及页面变化；停止会中止模型请求、暂停当前视频并阻止迟到结果预填。不会自动处理验证层。所有出口通过 `finally` 恢复 busy、按钮及加载圆环。

滚动阅读和逐页阅读总超时均为 5 分钟，分页反复回退不能无限循环。默认检测周期 500ms，内容与提交状态超时 30 秒，视频无进展超时 90 秒；暂停恢复间隔 3 秒，最多尝试 8 次。模拟测试使用独立短时限，不改变交付默认值。

## 章节测验的父页面提交确认

2026-10-09 只读现场 DOM 确认：内层章节测验使用课程主页面 `#workpop.maskDiv`，内部 `.popDiv` 显示 `#popcontent`「确认提交？」及 `#popok[role="button"]`「提交」。原流程只查题目文档而漏掉父页面确认。

`courseSubmitConfirmation(doc, owner)` 沿当前测验文档到课程 owner 的父链收集可见确认窗口，不扫描兄弟 iframe；嵌套弹窗去重，排除隐藏、禁用、验证码、人脸和取消控件。开始提交前若已有可见确认窗口则停止，避免把旧确认当成本次操作。初次提交及二次确认分别最多点击一次；确认后仍须等待当前测验平台完成状态，不能因按钮已点击就计为成功或进入下一章。


## 提交结果导航等待

提交后的结果页导航可能短暂使当前测验及父 iframe 不可读。`solveQuiz()` 在初次点击前保存 frame、workId 和父 frame 集合；仅 `context.submitting` 的有界等待阶段，`guardRun()` 容许该集合里的 iframe 短暂不可读。其他任务 iframe 不可读仍立即停止，人脸、验证码、账号、运行锁、章节及标签变化检查不关闭。

结果判断等待 frame 树全部可读，且结果文档仍在当前树内；不能用已脱离父树的旧完成页确认成功。仍检查 workId、明确的测验完成标记和目录剩余任务。30 秒内无法取得可靠结果则停止，记录提交结果不明，不重试、不计成功、不跳章。成功后清除导航等待范围，继续原任务/目录流程。


## 章节页面切换

章节导航页顶部提供左右两个子页切换，默认左侧「学习控制」，右侧「章节目录」。左页包含开始、停止、跳过、复制报告、自动提交选项与独立滚动报告；右页包含搜索、刷新、章节数量、完成状态与测验分数，目录使用剩余整页高度。公共底部状态保留。视频进度从运行租约的结构化秒数读取，不解析提示文字、不写入播放器。

`switchChapterView(view, {focus})` 只切换可见性、ARIA/tabindex 状态及目录读取；不更改 runner、配置或提交流程。返回章节页保留选中子页和搜索值。切换支持点击、左右箭头及 Home/End，在运行中仍可操作，回到学习控制后可以正常停止。


## 视频进度与面板尺寸

`emitRun()` 仅在 course-video 阶段将有限时长和播放秒数写入租约 data-video-duration / data-video-current；initCourseRunControls() 通过现有父子文档通知更新原生 progress。隐藏、停止、非视频阶段及未知时长不显示进度；值限定在0至时长，不修改 currentTime、playbackRate 或触发播放。

`initPanelResizing()` 使用 Pointer Capture 处理右边缘、下边缘和右下角，方向键可微调角落；默认最小320×260，狭小视口按可用空间缩减。userSize 仅保留当前面板内存，关闭重开保持，刷新页面恢复默认。updatePanelHeight() 和 setPanelPosition() 共用视口限制，缩放不重建页面、控件或运行器。


## 跨域 PPT 消息晚加载与去重

父侧 `courseDocumentBridgeRequest()` 在原30秒请求期限内，每250ms向两个已确认来源重发同一个ID的 read/step 消息；请求结束、取消、阅读器移除或 src 变化后清理计时器和监听器。不存在无限重试、自动跳章或伪造任务完成。子侧 `initCourseDocumentBridge()` 仅接受 mooc1 来源且属于本阅读器祖先链的窗口，缓存最近64个ID对应操作和返回结果，重发 step 只返回缓存，不再次滚动；同ID改换操作不处理。

阅读器根元素增加 `data-cx-document-bridge="v1.04"`，用于现场确认子模块是否运行；缺少标记不能直接证明唯一故障原因。运行器仍须取得真实平台完成状态后才继续。本次确认阅读器来源、路径和 `.fileBox ul li img` 结构匹配适配规则，页面仍显示旧面板；实际失败也可能是已安装脚本未更新或未刷新子 iframe，需安装后验证。


## v1.04 实际滚动区与多份 PPT（2026-10-09 后续修复）

后续现场已确认新版面板和子页面 `data-cx-document-bridge="v1.04"` 均存在，不能再归因于未更新。任务 PPT 有52张图片，实际 HTML 滚动根的 clientHeight=632、scrollHeight=36634、初始 scrollTop=0；原生页面交互后滚动位置能移动。未确认原 postMessage 失败的唯一根因。

子模块沿 `.fileBox ul li img` 的祖先查找有效 overflow 滚动容器，找不到则使用该文档 scrollingElement。每一步推进一个可视区域的80%，读取实际 top/height/total；图片未加载不推进。只操作资料内部，不扫描或滚动助手和章节目录。滚动位置百分比只表示阅读器位置，平台未确认不能计完成。

`courseDocumentReaders()` 在各资料容器内使用属性选择器枚举所有已确认的阅读器，按 DOM 节点去重，支持相同文件在多个 iframe 中出现。运行器逐份处理，每份单独编号、等待自己的平台标记，再进入下一份或下一章。

通信保留严格 origin/source 的原 postMessage 路径，新增油猴私有临时信箱：父端创建随机请求 ID 和监听器，把 read/step 写入该 ID 对应键，并只向目标 iframe 发送不执行滚动的 bind。子端绑定后通过 GM_getValue 和 GM_addValueChangeListener 接收请求，通过 GM_setValue 返回实际滚动尺寸；所有运输路径共用最近64个请求缓存，重复 step 不再滚动。

扩展消息 source=null 的兼容只适用于 bind：必须有真实 mooc1 父页 referrer 和 mooc1 事件 origin。直接 read/step 的 postMessage 仍要求本阅读器的真实祖先窗口；网页自身不能写油猴私有信箱。bind 监听最多32个、60秒过期，退出时清理；父请求完成/取消/换页会删除临时键与监听。信箱不包含课件地址、账户参数、题目、Key 或完成状态。新增 metadata grants：GM_deleteValue、GM_addValueChangeListener、GM_removeValueChangeListener。

接口依据：[油猴文档](https://www.tampermonkey.net/documentation.php#api:GM_addValueChangeListener)；source=null 的扩展环境说明：[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage#using_window.postmessage_in_extensions)。此现象在隔离浏览器中模拟覆盖，尚未确认真实课程此次故障就是该原因。


## 多层 iframe 的发送者与回传路由（v1.04，2026-10-09）

现场结构为 studentstudy → knowledge/cards → ananas/modules/pdf/index.html → pan-yz/screen/v2/file_*。桥接函数在顶层助手的执行环境中调用，即使目标 iframe 位于 PDF 文档，postMessage 的实际 source 仍是顶层窗口。旧实现只接受 view.parent，且父侧在 frame.ownerDocument.defaultView 注册回复监听，分别导致顶层请求被子端拒绝、回复等待位于错误窗口。新增真实 Chromium 四层结构测试，旧脚本稳定复现相同超时；捕获的 request source===top、source!==parent，没有模拟 MessageEvent.source、GM 或任务回报。

父侧 `courseDocumentBridgeRequest()` 使用执行环境的 window 注册和清理回复监听。子侧 `courseDocumentAncestorSource(view, source)` 遍历最多12级真实祖先，结合既有 mooc1 origin 和消息结构校验；同源兄弟窗口、自身、无关窗口和错误来源均不接受。回复通过已校验的 event.source.postMessage 发回实际请求者，不固定回 parent 或 top。直接父窗口发出的请求仍回复直接父窗口。GM bind 共用祖先校验；source=null 例外仍只允许非滚动 bind，且需父页 mooc1 referrer。

滚动操作、去重、超时和平台完成标记保护保持。子 HTML 另有 `data-cx-document-bridge-route="ancestor-v2"`，用于不递增 v1.04 的本地更新现场辨识；它只代表初始化运行，不代表任务完成。
