# 章节测验预填与提交修复

用户反馈线性代数章节测验显示分析结果后迅速离开，现场看不到答案写入或提交。静态审查确认，关闭连续失败保护后，原流程会绕过独立的自动跳过开关，并可能把预填或提交入口异常交给普通失败继续分支。

- 自动跳过不可作答内容只由对应开关授权。填写异常、回读不一致、富文本待保存或没有唯一提交按钮时，保留当前测验并显示具体原因。
- 分析部分成功时保留可可靠写入的答案。预填完成后复核原生答案，避免后续题目的事件清空前面已填内容。只有所有作答位置通过核对、且自动提交已开启时才提交支持自动提交的测验。提交成功仍以平台回读为准。
- 补充关闭失败保护时的测验保留、部分分析成功、后写清空前题和提交入口不唯一的用例。源码和差异已审查，本轮构建 v1.34.1 本地主脚本，未运行测试或真实课程验证。

后续本地补修：预填回读计数与提交确认标记在同一函数中重名，导致完整脚本解析失败、章节页入口消失。分别命名后重建完整安装脚本，并静态核对源码和产物中的引用。

用户补充截图确认，线性代数 1.2 的课堂测验为三道简答题，包含题干公式图片与富文本答案框，平台状态仍为待完成。源码中，已成功同步到原生表单的 UEditor 答案仍固定要求人工提交，预填前的部分加载、解析和分析错误则可能被章节继续逻辑放行。

- 已定位的测验等待题目和框架就绪。开启自动提交时，测验解析、模型调用或填写中断会保留当前栏目，面板显示具体失败原因。
- 仅在章节自动提交路径中放行已适配的 UEditor。整份测验仍须逐项回读，富文本答案须与编辑器正文、textarea 和同一原生表单的实际字段一致。点击唯一原生提交按钮后等待平台确认。普通一键生成沿用人工提交。
- 新增待完成状态先于题目出现、富文本表单字段是否可序列化的用例，并调整解析失败用例。执行范围为静态审查和主脚本构建，真实课程表现待人工验收。

后续截图显示线性代数 1.2 的答卷已显示「我的答案」，外层已显示绿色「任务点已完成」，助手仍在等待。原回读只识别答卷内页的完成标签。提交前记录原测验的待完成附件，提交后接受该附件的原生完成状态；其他附件的完成标记不计入，结果页明确指向其他测验时仍停止。新增本任务完成、兄弟附件完成及测验 ID 不同的回归用例，交付范围为静态审查和主脚本构建。

线性代数 2.7 的诊断记录显示，四道简答题首次提取时均不可写，约 0.25 秒后出现 `CX-PAR-008`。章节自动提交现在会在原有加载期限内等待已识别且仍在初始化的 UEditor。就绪后核对题干、题目和控件绑定再开始分析，保留对题目切换和控件替换的保护。

已遍历栏目、必做任务均完成而目录延迟时，显示「目录待确认」，沿用平台目录绿勾或剩余任务数为零确认整章。用户提供的 7 次历史超时没有逐章阶段，保留原记录。旧记录显示「阶段未记录」，新摘要导出章节序号、阶段和错误码。模型答案格式错误在本地报告单列，重试规则沿用原实现。新增编辑器等待、题干变化、目录延迟和脱敏导出的用例，按项目规则交付静态审查和主脚本构建。

线性代数 3.6 的截图显示第 1 题只有计算题标签，测验停在已核对 8/9 个作答位置。解析器已能识别没有可读取题干的题目；本次让题干缺失和可归到个别题目的材料或模型返回异常走待处理路径，即使关闭「自动跳过 AI 无法答题的题目」也继续后续任务。已经可靠写入的答案只在页面内预填，整份答卷保持未提交和待处理。课程身份变化、网络连接错误、验证和提交结果不明仍走原保护。补充 1 题及 9 题测验的静态核对用例。
