## 统一识别和写入

- 原生填空题的 1 个空与 N 个空均先走同一作答区域扫描，按实际原生字段和编辑器匹配，不固定为三空，也不按题号写特例。单空结果保留原题 ID 与原单编辑器绑定；普通单编辑器没有可靠的原生编号结构时保留既有路径。
- 依据可见“第N空”建立显式语义顺序，要求编号唯一、连续且与字段/行一一对应；发现时按空号排序。记录原 DOM 位置，分析后若行顺序或控件变化仍中止原计划。
- 多空题整体请求模型，要求全部空位各有稳定 ID 与一条答案；继续按 ID 校验完整性，不按分号、逗号或换行拆分答案。
- 预填规划按原题及空号顺序排列，即使模型答案数组或缓存插入顺序不同，也通过原绑定写入对应空。需要激活时点击同空的原生入口，展开并复核后逐空写入和回读。已有不同答案继续保护。
- 每空字段、实例、原生入口以及隐藏状态均按当时 DOM 重新读取；无法可靠关联时的错误细化为入口数量、ID 关系、容器归属、重复 ID、禁用状态或额外隐藏祖先等原因，避免不同原因都只显示同一句泛化提示。未知结构不按位置猜测。
