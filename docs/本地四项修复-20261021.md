## 1. 栏目异步加载与等待

原运行器在进入章节时固定 `tabIds`，后续 `lastTab` 使用该旧列表。完成等待只查看当前页控件与目录状态，新增栏目没有进入队列。

现以栏目 ID、`cardid`、当前 active 和实时顺序重新读取栏目，在任务处理结束、队列耗尽及完成等待期间发现新增栏目。单栏目导致原生栏目条隐藏时，使用唯一 active 节点确认归属；多 active、重复 ID、未知归属和内容身份变化保留明确失败处理。已有加载、完成等待期限保持原值。

栏目进展随运行记录保存到 `tabProgress`，导航恢复使用已处理身份与当前栏目 ID；旧任务节点继续去重，平台明确完成的任务记为 `already`。章节完成仍依据平台目录状态，失败和人工待处理状态保留实际原因。

## 2. 连续失败保护开关

自动刷课开关区新增“连续失败保护性停止”，初始关闭；持久化键为 `cx_course_failure_protection_enabled`。每轮固定到 `protection.enabled`，运行中锁定，导航恢复沿用本轮值；旧记录缺少字段时按关闭处理。

启动恢复与每章结果处理后的两处阈值检查均受此开关控制。计数、阈值和单章超时继续策略保留。人脸、验证码、用户停止、运行锁、账号/课程身份、页面及播放异常等保护继续使用原流程。已经触发停止的历史记录仍通过既有重新开始或重试入口处理。

## 3. 分析与预填解耦

原链路为 `prefill=false → questionLocalAnswerPolicy(manual) → analysisSkipped/prepareAnswerPolicies → questionCanAutoAnswer → 请求排除`。此外，分类与解答提示词均禁止数学计算推导，分类自动分析白名单缺少 `calculation`；解答归一化还会将解析截为 400 字并压缩换行。

现保留已有 `capabilities.analyze/prefill` 和题目 Schema。分析策略只处理题型、材料、模型能力及真实作答要求；预填策略独立检查写入许可。分类与解答提示词支持材料完整的数学计算及公式推导，`calculation` 加入分析白名单。

逐题核对所有图片引用及读取后的数据，继续复用图片格式/大小/解码、模型图像能力、`imageManifest` 和实际图像数据传递；分类与解答请求均携带所属题目材料。图片缺失或读取失败仅标记对应题目，取消及快照变化仍中止当前操作。

答案与解析完整保留换行，复合题保留分区域解析；面板与复制列表分别显示“AI 分析”和“自动预填”。所有题目不可写时，展示完整答案并提示手动填写；预填按钮按实际写入候选启用。UEditor、附件上传、绘图等控件继续保留写入保护，人工答案保护、快照校验和提交完成条件沿用原流程。

## 4. 原生倍速

原操作为 `menu.show()` 加 `vjs-hover` 后立即重读，随后将能力状态、播放器、按钮、旧目标节点和两处可见性校验统一报告成 `menu-changed`。失败发生在尝试记录之前，因而播放轮询会重复展开。用户现场的真实悬停后才发生脚本点击，与可见性条件相符；旧报告没有记录具体失败分支。

现按配置、技术支持、禁用提示、播放器/视频绑定、按钮/选项归属、唯一合法档位校验后，优先使用播放器正式 `playbackRate(target)` API，目标为原生最高且不超过 2x 的加速档位。API 缺失才使用原生 `pressButton()/unpressButton()` 展开菜单、重新取得可见目标并点击。API 调用被拒绝后结束该轮尝试。

复用现有播放轮询：准备窗口 3000ms，改速后实际速率确认窗口 2000ms。菜单或按钮重建沿用原期限；每个视频/播放器/媒体加载周期最多执行一次改速。以 `video.playbackRate` 回读确认，恢复原速后仅记录结果。失败时继续视频播放，保留倍速关闭与视频信息识别互斥规则。

停止、人工等待、定位、结束和换页清理本次菜单状态；新视频、播放器或媒体加载周期重新识别。倍速报告包含实际速率、操作方式和具体原因。本轮未修改播放位置、进度上报和平台学习记录。
