# 灰度服务器入口修复

用户反馈：`mooc1-gray.chaoxing.com/mycourse/studentstudy` 顶层及三层测验 iframe 均无入口，测验路径为 `/mooc-ans/work/selectWorkQuestionYiPiYue`，存在三个题目节点。

## 静态结论

1. 旧的课程服务器判定仅覆盖 mooc1、mooc1-数字与两个固定站点，灰度顶层学习页被排除。此规则也用于启动交接、队列和文档来源，须同步处理。
2. `studyOwnerDocument` 原先在第一个不可读祖先处结束查找。同源顶层与测验之间存在跨域中间层时会丢失顶层归属；改为逐层尝试读取，不绕过同源策略。
3. 启动流程和一次刷新内串行调用多个功能，没有分阶段捕获。前置功能异常会阻断其余初始化；现按功能隔离，并通过已有安全诊断记录及 Console 标注阶段，不输出原始错误内容或页面参数。
4. 元数据已匹配全部 chaoxing.com、xuexitong.com 子域，且未设置 noframes；测验初始化依据本地题目结构，不依赖顶层课程域名。仅凭灰度域名遗漏，无法确定子测验无入口的现场原因。源码没有新增网页 script 注入或跨域文档读取；各 iframe 仍由篡改猴独立执行完整脚本。

## 修改边界

允许的课程服务器为官方根域下 `mooc数字`，可带一个或多个字母数字部署后缀；不接受无关子域、嵌套域或伪造后缀。课程学习页仍校验原有路径和 DOM。跨文档通信保留精确 HTTPS origin、来源窗口、祖先关系、随机信箱及课程身份校验。文档桥保留既有阅读器跳转目的地，同时增加当前已确认 iframe 的精确 origin。

用户已授权将本次修复以 v1.33.3 发布。已补充针对性用例但未执行；未做语法检查、运行时检查或真实课程操作。后续只需用户/反馈者安装候选脚本，确认顶层及测验入口；若仍缺失，按 Console 的初始化阶段记录和篡改猴加载状态继续定位。
