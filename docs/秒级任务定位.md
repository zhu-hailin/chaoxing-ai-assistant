# 秒级定位可执行任务点

本地版本保持 1.20 / npm 1.0.20。本轮只调整任务定位与就绪等待，保留已有“其他功能”、视频播放、答题及完成判定。

## 根因与实现

上一候选串行读取栏目，空课件和讨论被归为未知，进入栏目后还会固定等待 2 秒。完整 HAR 响应另有平台工具的隐藏配置与搜索输入框：这些控件位于栏目正文之外，本轮将静态内容校验限定在 `.ans-cc`，全页仍检查任务、未知框架与验证标记。

| 环节 | 当前行为 |
| --- | --- |
| 扫描范围 | 从冻结的课程/当前栏目边界开始，跨章节统一扫描 |
| 并发读取 | 全局最多 4 个在途请求，最多前瞻 4 章，每章最多预读 4 个栏目槽位 |
| 顺序 | 响应可乱序，按章节和栏目顺序消费；最早未知项优先进入页面核实 |
| 目标确定 | 停止新增读取，取消更后面的在途请求，只原生跳转到目标 |
| 缓存 | 当前页面内存、最多 60 秒；共享相同读取的进行中 Promise |
| 失效 | 目录任务数、栏目 cardId 或账号/课程变化，以及本地任务完成时按章失效；刷新清空 |
| 就绪 | 对照目标栏目、Document URL、加载状态及实际任务控件，已就绪立即处理；过渡状态沿用 2 秒读取间隔与最多 5 次重试 |

缓存保存标准化任务摘要和栏目定位信息，设置变化重新计算任务资格。未知或失败结果不会作为“无任务”证据。进入目标后由实际页面重新核对；章节测验关闭时记录 `manual-pending`，保留平台未完成状态。

原生同源 GET 沿用 `studentstudyAjax` 与 `knowledge/cards`。预读 HTML 放在脱离页面的 template，静态扫描 mArg JSON，不执行返回脚本、不挂载预读媒体。取消最后一个读取消费者时终止底层请求；迟到响应丢弃。

## 有证据的无任务页面

- **静态课件**：完整 mArg、空 attachments、`.ans-cc` 仅有静态文字/图片等节点，且没有任务、模块、加载或验证证据时，判为无任务。空数组本身仍不足以排除。
- **讨论**：已验证的 `property.module="insertbbs"` 与 `.ans-insertbbs-module` 对应，元数据和模块 data 都无任务声明/ID，且没有其他未知模块或任务标记时，判为非任务；栏目名称可变化。
- 视频、PPT、知识图谱和未知模块继续复用原适配。最早的未知状态、验证、人工导航及提交不明保留原核实或停止路径。

开发者运行报告增加摘要请求、缓存命中、定位耗时、原生跳转、就绪命中与页面核实次数；定位回退原因仅记录固定代码。

## 验证与交付

回归覆盖脱敏原生结构、乱序响应、跨入口并发上限、部分消费者取消、迟到响应、缓存失效、设置变化、起点与恢复，以及真实控件就绪/延迟加载。

性能样本使用前 20 章各 4 栏、第 21 章出现目标、每次请求 100ms。同一组读取器分别测量串行参考、4 路冷定位和缓存命中；数据见《秒级任务定位回归结果.json》。只统计定位阶段，播放器资源加载另计。

真实用户课程待换装验收：前面栏目不再逐一打开、关闭测验提交后的目标选择、从当前第③栏开始、刷新恢复，以及视频/PPT正常处理。实际耗时随网络和课程结构变化。

README、`.publish`、版本号和 GitHub 保持原样。历史候选结果保留在原记录中。
