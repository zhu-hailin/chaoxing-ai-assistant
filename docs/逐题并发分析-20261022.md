# 逐题请求与并发分析

日期：2026-10-22。版本保持 1.28.1，本地修改，等待用户手动验收。

## 原因与范围

原有分批只限制输入题数和字符数，多个题目共用一次模型输出预算；请求截断时整批无结果，串行循环还会直接退出。

按用户最新要求，所有可靠提取的题目均独立请求，不按数学或其他学科区分。不增加作答适用性分类、答案正确性判断或相应提示。保留题目材料、模型输入能力、响应格式和预填关联校验。

## 本次实现

- 新增小型并发调度模块，复用原模型请求、响应规范化、图片准备、联网检索和动作规划。
- 模型设置新增“AI 分析并发数”，全局键 `cx_analysis_concurrency`，默认 3，整数范围 1–7。设置修改用于下次完整分析；本轮及未完成重试沿用启动值。
- 每个现有作答单元单独请求模型，保留原题和子单元映射；空闲槽位立即调度下一题。
- 答案成功后按原请求 ID 存入本轮 Map，渲染时按原题顺序投影。未完成重试和重试本题均跳过成功结果，复用已取得的逐题检索证据。
- 联网检索保持串行，各题最多沿用现有两次搜索工具使用和三条证据限制；解题队列和检索均遵守共享冷却。
- NETWORK、TIMEOUT、HTTP 429/502/503/504 最多尝试三次，退避为 2 秒、4 秒并加入抖动；JSON 或必要字段结构错误最多重试一次。题目 ID 错配、权限或配置错误不自动重试。
- CX-RES-004 截断直接记为该题失败，可手动重试；不接受残缺 JSON，不修改模型、推理强度或输出上限。
- 解析 Retry-After 的秒数和 HTTP 日期，仅保存等待时长；超过 60 秒的服务商等待转为暂停。连续五次临时失败暂停新增请求，在途成功结果继续保留。
- 每题分别显示等待、分析、重试等待、成功、失败、跳过和取消，面板显示汇总进度和真实错误码。
- 请求、返回、合并和等待期间持续校验快照、任务代次、配置及凭据；手动停止或页面离开时取消请求和等待，旧代次响应丢弃。
- 图片请求补充原有 groupId、parentQuestionId 与来源题目 ID，仅按当前题目的既有图片引用发送材料。共用图片保留来源，合并图像解析时保留各图片 ID。
- 面板、章节测验及视频弹题在仍有运行或失败任务时保留成功分析结果，停在预填前；完整分析后的原生写入、已有答案保护、同步回读和提交约束保留。
