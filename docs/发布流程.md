# 版本发布约定

每次正式发布递增 0.01，使用 GitHub Releases 展示版本与简要说明。仓库根目录的完整 `学习通AI助手.user.js` 继续作为 README 一键安装和油猴更新来源，不移动或删除；发行版再附一份内容完全一致的 `chaoxing-ai-assistant.user.js`，使用英文附件名避免 GitHub 改写中文文件名。`sources/assistant-core.js` 是构建片段，不能作为安装附件。

1. 更新 `build_script.py` 中 VERSION、源脚本元数据、面板/预览版本、提取结果版本、阅读器标记和对应断言；npm/package-lock 同步版本。
2. 在 `CHANGELOG.md` 顶部添加新版本的简要功能和修复说明，并在 `docs/验证记录.md` 记录证据。区分模拟回归、代理现场验证和用户人工反馈，不推断未测试范围。
3. 构建并检查语法，执行完整回归。无行为变化的发布也确认生成脚本对应当前源码。保留备份，不覆盖用户修改的 README。
4. 使用 `python prepare_publish.py --skip-readme` 同步发布清单，检查差异和 README 哈希，提交并正常推送 main。只提交本次文件，不强制推送。
5. 创建指向该已推送提交的 `vX.XX` 标签和正式发行版，标题为“vX.XX · 简要更新主题”。正文简述修复、验证及安装方式，上传完整脚本，附件名统一为 `chaoxing-ai-assistant.user.js`。上传失败时保持草稿，补齐并核对附件后才正式发布。
6. 下载发行版附件并核对 SHA-256 与已测试脚本完全一致；确认 README 安装链接和脚本 @updateURL/@downloadURL 返回当前版本；确认发行版在仓库首页可见。

历史发行版附件保持对应版本，不用新文件覆盖旧版本。以后每次发布都新建自己的发行版与说明，不只修改同一个发行版的正文。
