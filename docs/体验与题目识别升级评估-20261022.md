## 1. 结论

**值得继续升级，优先处理图片归属、图片失败恢复和结果阅读体验，再扩展页面与材料识别。现有架构足以承接这些改动，适合逐项小范围实施。**

最推荐先做以下四项：

| 顺序 | 升级项 | 直接收益 | 改动规模 |
| --- | --- | --- | --- |
| 1 | 修正图片缓存复用时的来源身份覆盖 | 同一图片地址重复使用时，题号、选项和图片清单保持正确 | 小 |
| 2 | 收紧共用材料的识别边界 | 独立题目只带自己的图片，真正共用材料继续复用 | 中 |
| 3 | 图片读取失败支持单题恢复 | 一张图暂时失败后，只重读并分析该题 | 中 |
| 4 | 分析进度更新时保留阅读位置 | 正在看后面的题时，其他题完成不会把列表拉回顶部 | 小到中 |

本文标为“源码确认”的内容，是已经核对的代码行为；条件性场景会写明触发条件。真实学校页面的触发频率与升级效果，留到对应改动后的人工验收。本次只进行静态源码、调用链及差异审查，未运行测试、构建、浏览器或真实 API 请求。

## 2. 已有能力应当继续保留

以下能力已经存在，不需要重新开发：

- 所有题目独立请求，默认 3 路、可配置 1–7 路并发。
- 成功答案按题目 ID 保存，按原题号展示；已有单题重试和未完成重试。
- 有限重试、Retry-After、共享限流、停止与晚到响应丢弃。
- AI 分析与自动预填分离；mooc2 单多选及旧版章节测验已有独立适配。
- UEditor 的 `answerEditor{数字}`、`answer{ID}` 两种模式，以及原生写入、同步回读、已有答案保护。
- 题目图、文档和控件快照、结构化 MathML、表格与代码材料、带明确关联证据的多空题。
- 题目与刷课面板双向交接、位置尺寸交接及无题目时禁用导航。

后续继续沿用“页面适配器 → 题目图 → 请求单元 → 模型响应 → 受保护预填”的链路。界面新增信息优先放入折叠详情，不增加 AI 能否解题的预判或答案正确性弹窗。

## 3. 优先处理的四项问题

### 3.1 图片内容缓存与题目身份需要分开

**优先级：P1；源码确认。**

证据：

- [question-parser.js:89](../sources/question-parser.js#L89) 为图片建立自己的 ID、题号和来源描述。
- [implementation.js:1344](../implementation.js#L1344) 按题准备图片，并复用同一个 `preparedMedia`。
- [question-media.js:115](../sources/question-media.js#L115) 把已准备的完整记录按 `src` 放入内容缓存。
- [question-media.js:139](../sources/question-media.js#L139) 使用 `{ ...descriptor, ...value }` 创建新记录；缓存的旧 `value` 可以覆盖当前描述符中的身份字段。
- [question-media.js:182](../sources/question-media.js#L182) 再将这些字段写入发送给模型的来源清单。

**触发示例：**第 1、2 题使用相同图片 URL，但各有独立 `imageId`。第二题复用第一题的缓存时，Map 的键仍是第二题图片 ID，记录内部的题号、题目 ID、选项位置却可能保留第一题的信息。相同原图被用作题干和选项时，也有同类问题。

**建议改法：**缓存只保存图片内容字段：`mime`、`dataUrl`、`byteLength`、宽高和摘要；每次用当前描述符建立身份字段。构造请求前核对 Map 键、记录 ID 与原始来源描述符。继续保留原图内容去重。

**人工验收：**两题引用同一 URL、同图用于题干和选项、失败题再次读取缓存时，每份请求的题号和选项归属都与当前题一致。

### 3.2 展示分组不应直接等同于共用材料分组

**优先级：P1；共享规则已确认，是否命中取决于学校 DOM。**

证据：[question-parser.js:263](../sources/question-parser.js#L263) 使用最近的 `.mark_item` 建立 `groupId`；[question-parser.js:447](../sources/question-parser.js#L447) 将同组其他题的题干图片全部加入当前题的 `contextImageIds`。这些图片随后通过 [question-media.js:174](../sources/question-media.js#L174) 进入请求。

如果某个页面用一个 `.mark_item` 包住整组简答题，七道独立公式题即使分别请求，也可能各自携带其他题的公式图。这样既增加图片材料，也给模型制造题意干扰。

**建议改法：**保留现有展示分组，另外记录经过适配器确认的共享材料关系。只有共同材料节点、明确原生引用或已确认的题组结构，才生成跨题 `contextImageIds`。

**人工验收：**七道独立图片题每次只带本题图；一张材料图供三小题使用时，三小题都保留该共同材料。

### 3.3 临时图片失败应进入可恢复状态

**优先级：P1；源码确认。**

当前链路：

1. [implementation.js:1352](../implementation.js#L1352) 将图片读取失败转为 `uncertain/images`。
2. [implementation.js:1454](../implementation.js#L1454) 将对应题归入 `skipped`。
3. [implementation.js:1375](../implementation.js#L1375) 将 `success` 与 `skipped` 都视为本轮完成。
4. [implementation.js:453](../implementation.js#L453) 的逐题重试只接收 `failed/cancelled`；[implementation.js:1517](../implementation.js#L1517) 的任务恢复只接收 `failed/stopped`。

结果是：其他六题成功、一题图片暂时失败时，图片恢复后缺少“只重新读取这一题”的入口。重新分析全部会重复请求成功题。

**建议改法：**区分“暂时读取失败”“材料结构不完整”“模型不支持图片”“用户明确跳过”。暂时读取失败进入可重试状态，使用既有重试入口重新准备该题材料；成功结果继续保留。同步核对 `analysisComplete` 和自动预填入口，保持失败、主动跳过及完整分析各自的含义。

**人工验收：**七题中一张图片先失败、后恢复；只重读并请求这一题，原六题答案保持。真实材料缺失和不支持图片的模型仍显示准确状态。

### 3.4 进度更新不应重置用户正在阅读的位置

**优先级：P1；源码确认。**

证据：[implementation.js:1386](../implementation.js#L1386) 的进度输出最终进入 `renderResultList()`；[implementation.js:498](../implementation.js#L498) 整体替换结果节点，下一行无条件执行 `output.scrollTop = 0`。

并发任务开始、完成或重试时，用户阅读的后方题目会随重绘回到顶部，图片节点和选中的文字也会重建。此前的面板往返修复保留的是控制器状态，这里属于结果重绘的另一条链路。

**建议改法：**先区分“完整新结果”和“普通进度更新”，普通更新保存题目 ID 与卡片内偏移作为阅读锚点；再逐步按题目 ID 更新变动卡片，复用未变的图片与正文节点。主动重新提取时保留明确回顶行为。

**人工验收：**20 题、3 路分析，滚动至第 15 题；其他题完成和重试时阅读位置稳定，正在复制的文字保持可用。

## 4. 题目识别值得扩展的方向

### 4.1 扩充明确的文字作答题型别名

**优先级：P2；源码确认。**

[question-parser.js:330](../sources/question-parser.js#L330) 当前只将单选、多选、判断、填空、简答／问答／论述归入标准类型。明确标为“计算题”“证明题”“解答题”的题目会进入 `unknown`，再被 [question-parser.js:362](../sources/question-parser.js#L362) 的本地策略排除。

已经能分析的是“简答题标签下的计算内容”；可升级的是不同学校使用的题型名称。

**建议：**增加有明确来源的题型别名表，将已确认的文字作答类型映射到现有答案协议，保留原题型标签。自动写入继续依赖控件的独立资格。排序、匹配等结构复杂的题型单独适配。

**验收：**相同题干分别标为简答、计算、证明时均可请求；缺少可靠写入关系时只展示答案。

### 4.2 补齐 SVG、Canvas 材料的检测与读取

**优先级：P2；现有载体覆盖范围已确认。**

[question-parser.js:80](../sources/question-parser.js#L80) 主要收集 `img`；[question-parser.js:474](../sources/question-parser.js#L474) 的结构化材料分支支持 IMG、MathML、TABLE、PRE／CODE。MathML 已优先读取 TeX annotation。SVG 路径和 Canvas 像素尚无对应材料读取分支。

如果题目图形由 SVG path 或 Canvas 绘制，当前递归读取可能只留下周围文字，图形本身未进入请求。

**建议分两步：**先识别这类载体及其原生 TeX、无障碍文本，建立明确的材料完整性状态；再针对确认过的页面补只读转图适配。沿用现有图片来源、题目身份和模型图像能力检查，优先复用浏览器原生能力。

**验收：**相同公式分别采用 IMG、MathML、SVG 时，模型拿到等价材料；无法读取的 Canvas 保留真实失败状态。

### 4.3 用现有题目图补原生多空适配

**优先级：P2；扩展现有能力。**

[question-parser.js:492](../sources/question-parser.js#L492) 已支持显式 slots 和可靠的 `label[for]`；[question-parser.js:561](../sources/question-parser.js#L561) 可将多个已证实的空位拆成独立作答单元。普通页面若只提供平台自己的空位编号和字段属性，仍需适配器补关联证据。

**建议：**先收集一种真实多空页面，利用已有 `graphHints.slots` 输出“空位编号 → 控件”的唯一关系，不另建一套多空系统，也不按文本框数量推测小题。

**验收：**三空题得到三个稳定单元；第二空已有人工答案时保留；字段被调换或缺失时停止对应题写入。

### 4.4 限定当前有效题区，排除隐藏模板

**优先级：P2；条件性适配风险。**

[question-parser.js:14](../sources/question-parser.js#L14) 的普通候选收集主要处理重复祖先和视频弹题边界，未统一排除隐藏模板；[question-parser.js:442](../sources/question-parser.js#L442) 遇重复 ID 会停止解析。

学校页面如果保留隐藏题目模板、分页旧节点或不可见副本，可能多计题目或触发重复 ID。

**建议：**在具体页面适配器中限定当前有效题区，排除 `template`、`hidden` 及隐藏祖先。继续识别长页面下方已加载的题目，不以“是否处于屏幕视口内”作为题目筛选条件。

**验收：**隐藏模板不增加题数；屏幕下方题目正常提取；平台翻页后快照仅包含当前有效题区。

## 5. 体验升级建议

### 5.1 明确“重试未完成”和“重新分析全部”

**优先级：P2；交互缺口已确认。**

主按钮仍叫“AI 分析”，但再次点击会在 [implementation.js:1587](../implementation.js#L1587) 清理旧结果并开启全新分析；保留成功题的恢复入口是 [implementation.js:1515](../implementation.js#L1515)。

有部分结果时，突出已有“重试未完成”，将完整重开动作命名为“重新分析全部”。保持现有任务机制，不增加弹窗。验收时明确区分“只请求失败两题”与“用户主动重做全部题”。

### 5.2 失败题显式换配置时，保留其他成功答案

**优先级：P2；独立功能升级，改动规模中到大。**

当前模型配置变化会通过 [implementation.js:1505](../implementation.js#L1505) 使整轮任务失效；[implementation.js:1523](../implementation.js#L1523) 也要求恢复配置与原轮一致。这有助于隔离不同运行配置，但使“六题成功、一题截断后主动换模型”需要重新开始整轮。

**建议：**在单题重试中提供用户明确选择的配置，为该题新建冻结配置的请求记录，其他成功题保留原答案及原模型信息。继续核对题目快照、请求目标、任务身份与晚到响应；保持截断响应拒收，也保持用户对模型及思考强度的明确选择。

**验收：**只给失败题换配置时，六道成功题不重复请求；原题材料变化时按既有规则失效；请求仍服从本轮并发和限流上限。

### 5.3 增加轻量定位、单题复制和大图查看

**优先级：P2；功能候选，可分开实施。**

现有 [题目页面](../sources/panel-template.html#L99) 主要提供整份列表操作；[implementation.js:440](../implementation.js#L440) 按题号展开所有卡片，[implementation.js:907](../implementation.js#L907) 的复制入口面向整份列表。图片在 [implementation.js:404](../implementation.js#L404) 中仅作为列表预览。

建议以三个小功能改善长试卷：

- **题号定位与“全部／未完成”过滤：**只改变显示，保留原题号、结果 ID 和调度顺序。
- **单题复制：**只复制该题答案及解析，减少手动选取。
- **点击原图查看：**宽表格和公式可滚动查看，保留题号、选项和共用材料标记；关闭后返回原位置。

验收重点是过滤后不重编号、复制不串题、大图来源准确，所有浏览动作保持分析与预填状态。

## 7. 推荐实施顺序

1. **第一阶段：保证现有图文题链路稳定。**处理图片缓存身份、共享材料边界、图片失败恢复、进度重绘阅读位置。四项分别提交和验收，方便定位变化。
2. **第二阶段：扩大真实页面覆盖。**增加明确文字题型别名；按真实页面补 SVG／Canvas、多空和隐藏模板适配。
3. **第三阶段：减少重复操作。**完善重试与完整重开命名，加入单题复制、题号定位及原图查看。
4. **第四阶段：提升长任务恢复和响应速度。**再安排材料流水线、单题换配置和可选结果暂存。

每项改动继续保留已支持页面、原题 ID、图片来源、独立预填资格、人工答案保护及平台原生交互。新增能力按适配器和明确证据扩展；业务状态不因筛选、查看图片或切换面板而改变。
