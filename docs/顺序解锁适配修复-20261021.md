# 顺序解锁适配修复 · 2026-10-21

## 来源和根因

基于 `D:\Project\xuexitong` 本地最新源码。用户提供的现场为 `/mycourse/studentstudy`：4.7 的 `.posCatalog_name` 有原生 `getTeacherAjax(...)` 入口；4.8、4.9、4.10 没有导航处理函数，处于顺序锁定状态。

静态调用链确认：

- `readCourseCatalog()` 原先直接把现代目录的 `.posCatalog_name` 保存为 target，没有判断导航能力。
- `locateAhead()` 只检查 target 节点连接；`findNextCourseTask()` 最多同时预读后续四章，`courseTaskProbe()` 会构造章节摘要和栏目读取请求。
- `processChapter()` 直接点击 target，随后等待 active 与内容变化；超时继续未检查顺序边界。
- 重试把 target 缺失等同于章节丢失；运行停止的通用分支可能覆盖前章结果；面板控制更新会统一恢复目录按钮可用。

## 实际修改

- `course_catalog.js`：增加分组、可导航、待解锁、入口未确认状态；支持 `getTeacherAjax` 内联事件、原生 javascript 链接、属性绑定 onclick 及行级冒泡入口。现代目录已识别 getTeacherAjax 模式而某章缺少受支持入口时，视为待解锁；未识别的事件模式保留为入口未确认。当前已加载章节结合 active 和实际 cards URL 证明身份后，仍可处理已有内容。
- `sources/course-page-adapter.js`：实时目录替代旧节点快照；导航状态进入摘要缓存代际。预读限制在可访问前缀内，在请求调度、缓存读写及逐栏目读取处检查入口；边界作为独立结果传给运行器。进入当前章节后的摘要读取使用当前运行保护，预读范围检查仅用于预读期间。
- `sources/course-runner.js`：前置章节确认完成后才启用解锁检测，每 500 毫秒重读、最多 15 秒、发现入口立即继续；同一边界的重建不重置期限，已可进入章节不增加等待。超时、跳过和人工待处理的前置任务遇锁直接停止。待解锁和入口未确认分别列入报告与重试，后续章节保留本轮未访问原因，保留前章真实结果。等待期间保持账号、课程、运行锁、章节、栏目及手动停止保护。
- `implementation.js`：控制更新保留目录按钮的导航可用状态。
- `CHANGELOG.md` 和本记录：新增未发布说明，版本保持 1.27。

保留既有 AI 分析、选择题与 UEditor 预填、播放器倍速、动态栏目处理、提交保护和连续失败保护流程。只使用平台已有章节入口导航；本次没有修改任务上报或学习记录。
