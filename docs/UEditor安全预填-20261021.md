## 本次实现

- 只为上述旧版路由的明确填空/简答题识别 UEditor。通过 textarea ID 与现有实例 key 精确查找，核对唯一 ID、唯一表单 name、同题归属、form1、就绪状态、可编辑 body、容器/iframe/document/body 引用以及原生方法。实例或控件跨题共享、禁用、替换、销毁、未就绪或混合多个文本响应时，保留手动填写。
- 不创建或初始化编辑器，不猜测 `ueditorInstantN`/`ueditor_N`，不修改实例配置。
- 经完整关联确认后，能力与题目图放行该 textarea 的 UEditor 专用写入路径；未知富文本继续受保护，AI 题目及图片分析链路保持独立。
- 用原生文本节点生成安全的段落和 `<br>`，将模型中的 HTML 作为文字转义，保留换行与解题步骤。每次执行仅调用一次 `setContent(html, false)`，再经原生 `sync()` 同步，不直接赋值 textarea 或修改平台答案字段，不主动调用保存接口。
- 写入前保护已有内容：不同文本、非文本附件/公式/图片、编辑器与 textarea 不一致均跳过；已有相同且同步的文本记为 `already`，不重复写入。
- 复用整份动作计划执行前检查及逐题快照保护，新增实例、方法和答案 iframe 的生命周期检查；同时监听 iframe 内真实人工输入、点击、粘贴等事件，发现介入即停止后续动作。
- 回读 `getContent()`、iframe body 与 textarea，以段落/换行、实体和空白归一后的语义文本对比目标答案，兼容原生 HTML 规范化。最多等待 1 秒，不重复调用写入。回读不一致记为 `unverified`，停止后续动作；异常保留此前成功及部分写入摘要。
- 预填摘要保留一次“请手动保存或提交”；刷课中的新增 UEditor 路径也保留为人工保存/提交，不据此进入自动提交。普通控件原有提交设置和视频弹题路径保留。

[UEditor 官方 Editor 源码](https://raw.githubusercontent.com/fex-team/ueditor/dev-1.5.0/_src/core/Editor.js)用于核对 `setContent()`、`getContent()`、`sync()`、就绪及同步 API 语义。具体页面适配依据为用户提供的现场结构。
