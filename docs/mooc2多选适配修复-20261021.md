# mooc2 多选适配修复 · 2026-10-21

## 依据与根因

基于 `D:\Project\xuexitong` 本地最新源码，先阅读 AGENTS.md。用户提供 `/mooc-ans/mooc2/work/dowork` 的只读 DOM 诊断：多选使用 `.num_option_dx`、`.check_answer_dx`、`role=checkbox`、`qtype=1` 与 `addMultipleChoice(this)`。第 11 题 qid 为 405935328，人工选中 C，CSS、ARIA 和 `answer405935328=C` 一致；第 12、13 题为空。

静态源码确认原 mooc2 分支固定读取 `.num_option`、要求 `addChoice(this)`，使真实多选的字母被读成空值，从而出现重复选项键。`finishQuestion()` 又将 mooc2 的完整写入适配失败用于关闭 analyze，经过本地答案策略、策略准备和 `questionCanAutoAnswer()` 后排除了这些题。状态回读固定判断 `check_answer`，也无法识别 `check_answer_dx`。

## 源码修改

### 解析与 AI 筛选

`sources/question-parser.js`：

- 传入已提取的题目 ID 与明确题型。单选保留 `.num_option + radio + addChoice + qtype=0`；多选增加 `.num_option_dx + checkbox + addMultipleChoice + qtype=1`。判断题保留原有 radio/addChoice 读法及组内 qtype 一致性检查。
- 显示字母用于 AI 与动作键；实际 data 仅保留在私有运行时绑定中。保留唯一字母、唯一内部编码、qid 与当前题一致、单一字母及内容节点、原生处理函数和控件组归属检查。
- 隐藏答案同时检查 id/name 的唯一性、实际 hidden input、所属表单及题目归属，复用原快照检查，并比较新的题型、标记类别及材料可靠性字段。
- 用 `contentValid` 判断材料提取，用 `valid` 独立判断原生写入能力。材料与题型可靠时，缺失保存字段或原生控件未适配不再单独阻止 AI 分析；题型、题目身份、字母或材料歧义继续限制分析。
- 已静态检查 `prepareAnswerPolicies()`、`analysisSkipped()`、`questionCanAutoAnswer()`、`questionPrefillPolicy()` 和题目图请求投影；复用现有筛选和结果展示，不修改通用策略及其他页面适配器。

### 状态回读与自动预填

`sources/question-actions.js`：

- 按明确题型读取 `check_answer` 或 `check_answer_dx`，核对当前题 ID、题型、全部选中项及 ARIA。未选中选项允许 ARIA 缺失；属性存在时须与 CSS 一致，已选中项继续要求明确的 aria-checked=true。
- 单选保留既有内部值回读方式。多选以原生隐藏字段作为编码序列，逐段唯一解码各选项的实际 data，再与 CSS 选中集合逐项核对；重复编码、歧义、未知值、额外或缺失选项均不能确认成功。
- 既有本地记录描述 data 无分隔拼接；新现场仅提供单个已选值 C，未提供多个选中项的完整原生函数。实现保留平台实际输出顺序，不推断 DOM 排序或 AI 答案顺序；其他编码格式保持安全未确认。
- 复用原动作规划、原生行点击及每步/最终 CSS、ARIA、隐藏字段验证，不直接修改样式或隐藏答案。执行前再次确认已选目标，避免反选。
- 已有相同完整答案回读确认后记为已有答案；不同或部分人工答案保持跳过，现场第 11 题仅 C 时不会自动补成其他组合。回读失败保留部分填写记录并停止后续动作。

`question-context.js` 中的原绑定身份检查继续调用扩展后的 `sameMooc2ChoiceBindings()`。旧版章节选择、原生 radio/checkbox、UEditor 及视频弹题的专用分支未修改；本次不提交测验。
