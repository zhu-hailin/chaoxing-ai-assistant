# 课程列表入口与跨课程队列研究

日期：2026-10-23  
依据：本地 v1.30 源码、当前个人空间及课程列表的只读 DOM。  
范围：研究入口位置、原生课程导航及现有刷课流程的复用方式。

## 1. 结论

可以实现。建议在现有刷课流程外增加一个小型“课程队列”，按用户选择的顺序逐门处理课程。

入口按用户标注，放在课程列表工具栏的 **“学习规划助手”左侧**，与它、搜索框保持同一行，按钮名称为“学习通AI助手”。点击后复用现有助手窗口，进入课程队列。

整体关系：

```text
课程队列
  ├─ 课程 A → 现有章节定位、视频、资料、测验及顺序解锁流程
  ├─ 课程 B → 同一套现有流程
  └─ 课程 C → 同一套现有流程
```

这是主脚本内的扩展，沿用目前分模块开发、最终合并成一个用户脚本的方式。接口候选版和配套扩展继续暂缓。

## 2. 已确认的页面结构

个人空间外层地址为 `https://i.chaoxing.com/base`。实际课程卡片和目标工具栏位于 `#frame_content` iframe 中，其声明入口为 `https://mooc2-ans.chaoxing.com/visit/interaction`。

| 内容 | 当前现场结构 | 用途 |
| --- | --- | --- |
| 课程区域 | `#courselistArea`、`#courseList` | 入口与课程列表适配范围 |
| 学生在读课程 | `#stuNormalCourseListDiv` | 读取“我学的课”，避免混入“我教的课” |
| 工具栏 | `#courselistArea .btn_group` | 挂载助手入口 |
| 原生规划助手 | `.assistantBtn` | 入口相邻定位依据 |
| 搜索 | `.dataSearch`、`#searchInput` | 保留现有布局及搜索功能 |
| 课程卡片 | `.course.learnCourse` | 提取课程名称、身份、状态及原生入口 |
| 课程链接 | 卡片内 `h3 a`，现场与封面链接一致 | 沿实际平台入口进入课程 |
| 任务点进度 | `.btm-cover .l-txt` | 读取平台提供的 `已完成/总数` |
| 已结束课程 | `#isState` 下 `.not-open-tip` | 识别“课程已结束” |

现场共读取到 35 张课程卡片，其中 4 张有“课程已结束”，15 张提供任务点比例。这是当前渲染列表的数量；页面有文件夹功能，队列界面应明确展示实际已读取的课程。

现场任务点示例：大学物理 B 为 `84/96`，线性代数 A 为 `34/49`。部分课程完全没有任务点比例，这类课程应显示“进度未提供”，进入课程后交给现有定位器判断。

课程链接当前使用平台 `/visit/stucoursemiddle` 入口，包含 `courseid`、`clazzid`、`cpi` 等参数，并默认 `target="_blank"`。卡片 ID 与链接中的课程 ID 在已检查样本中一致。

### 入口应在 iframe 本地挂载

此处与此前课程首页的域隔离问题相似。入口应由课程列表 iframe 内的脚本直接挂载，采用工具栏自身布局，放在规划助手左侧；父页面负责需要由顶层展示的窗口协调。

继续使用私有跨页通信及已有窗口机制，避免依赖父页面直接读取子页面 DOM。现有脚本匹配规则已经覆盖上述域名。

## 3. 用户看到的流程

1. 在指定位置点击“学习通AI助手”。
2. 助手列出当前读取到的课程，用户选择本次课程及顺序。
3. 配置现有刷课选项，点击“开始队列”。
4. 自动进入第一门课，使用现有流程完成可处理的任务。
5. 记录这门课的实际结果，进入下一门课。
6. 队列结束后显示逐门结果；需要人工处理、待解锁和待重试的任务仍可查看。

界面建议只增加必要内容：课程名称、任务点进度、队列状态，以及“开始队列 / 停止队列 / 跳过本课程”。学习页面原有“跳过本章节”继续只控制章节。

运行时可显示“课程 2/5 · 大学物理 B”，具体任务进度继续使用现有章节报告。正常切换不逐门弹窗确认，详细待办放在可展开的结果中。

课程采用主动选择，已结束课程标明原因并禁用。首次使用可按页面顺序展示，避免默认把整个账号的历史课程都加入本次运行。

## 4. 复用已有代码的接法

| 现有位置 | 已有职责 | 建议接入方式 |
| --- | --- | --- |
| `implementation.js` | 页面初始化、面板挂载、iframe 更新监听 | 增加个人空间及课程列表适配入口 |
| `sources/course-controls.js` | 刷课设置、启动、停止、重试、提交授权 | 复用配置与控件风格，区分课程队列和单课程动作 |
| `sources/course-home-launch.js` | 原生导航、课程身份核对、一次性跨页启动交接 | 每次进入课程后继续复用；补充内部队列关联 |
| `sources/course-runner.js` | 当前课程的章节与任务执行、停止保护、恢复和报告 | 保留执行逻辑，只提供外层所需的结构化结束结果 |
| `sources/panel-template.html` | 助手窗口界面 | 增加紧凑的课程队列视图 |
| `build_script.py` | 模块合并 | 纳入新增模块，继续输出完整用户脚本 |

新增模块控制在两类职责：课程列表适配、课程队列调度。沿用现有存储、错误处理与页面交接工具，不引入第三方依赖或第二套刷课系统。

现有运行器的 `queue` 是单门课的章节列表。课程卡片应由外层队列管理，避免与章节恢复、索引和身份校验混用。`studyOwnerDocument()` 继续只识别真正的学习页。

## 5. 最关键的改造：课程结束怎么判断

源码中，`courseRunner` 在章节循环结束后设置 `report.status = 'done'`。这时报告里仍可能存在人工任务、超时、跳过或未处理章节。外层调度必须结合 `coursePendingChapters(report)`、任务结果、解锁边界及停止原因判断下一步。

| 课程结果 | 列表中如何表示 | 课程队列动作 |
| --- | --- | --- |
| 平台已确认任务点全部完成 | 任务点已完成 | 进入下一门 |
| 本轮可自动处理的任务已结束，仍有明确人工待办 | 已处理，需人工 | 保存待办，进入下一门 |
| 到达顺序解锁边界 | 待解锁，并记录前置章节 | 保留边界，结束本门本轮处理，进入下一门 |
| 真实任务超时或普通临时失败 | 待重试 | 沿用已授权的继续策略；要求停止时停下队列 |
| 用户主动跳过本课程 | 已跳过 | 取消当前运行，清理后进入下一门 |
| 用户停止队列 | 已停止 | 取消当前及后续启动 |
| 验证码、人脸识别、登录或账号异常、提交结果不明确 | 等待人工处理 | 停下整个队列，保留现场 |
| 连续失败保护触发、身份或运行锁校验失败 | 已停止，保留原因 | 停下整个队列 |

“可完成任务”在这里指本轮具备访问条件且现有执行器支持处理的任务。任务超时保留待重试状态；人工任务和锁定任务保留各自原因。最终统计分别显示实际完成和本轮处理结果。

顺序解锁继续遵守既有规则：先处理当前章节，完成后等待目录更新，最多等待 15 秒；仍未解锁则记录边界。课程队列只接续到另一门课程，不改变本门课程的导航权限。

现有保护性停止有些仅返回文字原因。实现时应补充少量结构化结束原因，避免通过模糊匹配提示文字决定是否继续下一门。

## 6. 跨页面与标签页建议

建议自动队列复用一个绑定的标签页。每门课沿页面中当时有效的原生链接进入，再由已有首页启动交接接入学习页。

```text
课程列表 → 原生课程入口 → 课程首页 → 学习页及现有执行器
    ↑                                         │
    └── 返回列表、重新读取下一门原生入口 ───────┘
```

这样能沿用 GM 标签页身份和恢复记录，也能避免每门课程都新建标签页。队列导航使用原生链接的实际地址，在绑定标签页内执行；用户平时手动点击课程卡片的行为保持原样。

每次进入下一门前重新读取课程卡片，核对当前课程、班级和 `cpi`，避免长期保存可能过期的入口地址。页面只有部分课程已加载时，应显示实际可用范围；文件夹内的课程需要从对应原生列表读取。

现有首页交接期限是 120 秒，适用于一次进入学习页。跨课程队列应为每一次跳转创建新交接记录；整个多小时队列有自己的生命周期。

具体原生中转链路和同标签页衔接仍需人工页面验收。本次未打开课程链接。

## 7. 状态、停止及授权衔接

- 保存队列 ID、课程顺序、每门课身份、当前课程、运行轮次、绑定标签页及逐门结果。记录不保存 API Key。
- 学习页报告必须同时对应当前队列、当前课程及本次运行；导航中的旧响应不得推进下一门。
- 课程结束回调应等待 `runner.start()` 返回并完成清理、释放运行锁，不能只监听最先出现的 `done` 事件。
- 刷新、章节导航恢复、课程间导航分别记录状态。正常章节交接继续由现有恢复流程处理，避免被当成整门课程结束。
- 学习页点击“停止”时，先撤销队列继续权限，再停止现有运行器。这样停下当前视频后，外层不会继续启动下一门。
- 自动提交仍需明确授权。队列开始时把授权范围限定为本次选择的课程；进入每门课时生成相应的一次性运行授权，取消、结束及账号变化后失效。
- 保留倍速、后台播放、视频间隔、学习休息设置；跨课程跳转应延续本轮学习时长，避免通过换课程重置休息安排。

账号识别仍有一个实现前需补齐的细节：当前读取到的每门课程入口都有 `cpi`，但本次有限 DOM 检查尚未确认个人空间可复用的稳定账号 ID 来源。应复用既有可信身份来源并逐门核对，避免使用昵称作为账号凭据。页面中的 Token 字段不作为队列身份。

## 8. 建议的实施范围

一次完整交付可以覆盖：指定位置的入口、课程选择及排序、当前已加载课程读取、单标签页跨课程调度、逐门报告、停止和重试、刷新恢复、顺序解锁兼容。

暂不扩展到后台独立插件、跨课程并行、远程课程接口或自动扫描所有文件夹。主脚本内的两层调度已能实现用户提出的逐门学习流程。

人工验收重点：

- 入口在规划助手左侧，课程列表重新加载后只出现一次。
- 只读取当前学生课程，课程与班级重名时仍能准确区分。
- 一门处理结束后只启动指定下一门，章节中转与刷新不重复启动。
- 人工待办、超时、解锁边界和真实任务完成分别保留正确结果。
- 手动停止、验证码、人脸、账号切换及提交异常时停止整个队列。
- 单门课程原有入口、刷课设置、章节定位及恢复继续正常使用。
