# 首页章节域隔离适配

后续用户现场已经显示入口和目录，但点击助手目录未触发原生章节点击；用户日志确认消息已到达章节页。导航命令的进一步修复见 [首页目录导航命令同步](首页目录导航命令同步-20261023.md)。下文保留本轮实现和待验收范围。

## 现场证据与根因

用户在真实课程首页控制台提供：父页来源是 `https://mooc2-ans.chaoxing.com`，`document.domain` 为 `chaoxing.com`，iframe 无 sandbox；`frame.contentDocument` 为空，直接读取 `frame.contentWindow.document` 抛出 SecurityError。顶层助手、标题和课程身份检查均正常。

此前实现依据 URL 同源直接读取父子文档。首次入口方案依赖章节访问父页；补挂方案改为父页访问章节，仍依赖同一项被浏览器隔离的 DOM 访问，所以用户现场继续失败。目录读取和启动选章同样经过这条链路，需要一并适配。

## 修改范围

- `sources/course-home-launch.js`：章节只读取自己的 DOM，并按自身 URL、原生身份字段及首页 referrer 核对上下文；本地创建入口，通过原有来源、iframe 窗口及课程校验打开顶层主面板。同源且文档可读的首页保留直接访问路径。
- 首页读不到章节文档时，使用已有 GM 存储与 postMessage 能力建立私有绑定：父页生成随机 ID，绑定当前 iframe、声明地址、课程／班级／cpi 和 GM 标签页；章节匹配实际地址及原生身份后绑定当前文档随机 ID。消息只传唤醒 ID，目录数据与命令保留在脚本私有 GM 存储。
- 目录继续使用原解析函数；同步纯数据，不复制 HTML、DOM 引用、API Key 或提交设置。接收方限制条目及字段长度，核对章节 ID 唯一性、分组归属、无环层级和快照版本；刷新、文档变化及离开使旧数据失效。
- `course_catalog.js`：展示绑定目录的分组、完成状态、未解锁与未知入口，继续支持搜索及定位未完成。用户点击后创建限时单次私有导航命令；章节重新读取原目录、验证 ID、权限、原生控件与处理函数后点击原节点。没有构造章节内容请求或修改平台状态。
- `implementation.js`：恢复章节侧入口初始化，消除显示入口时读取父文档的依赖。

连接每 500ms 准备一次、最多 15 秒；绑定后仅在原生目录有变化时同步。手动导航等待最多 5 秒，执行前消费一次命令；超时、离开及 iframe 更换清理监听、定时器和私有记录。手动刷新目录可重新建立绑定。

启动仍使用原私有启动记录、原生章节导航与 `courseRunner.start()`；章节侧重新识别目录，保留首个未完成任务选择、顺序解锁边界、完整栏目检查、账号与课程身份、取消、运行锁和自动提交授权。学习页、题目解析、预填、视频、倍速及后台播放流程不改动。不设置或修改平台 document.domain。
